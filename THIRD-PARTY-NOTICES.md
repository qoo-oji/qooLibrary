# Third-Party Notices

qooLibrary vendors the following third-party components. Each is isolated
under `ThirdParty/<name>/` and is **not** covered by qooLibrary's MIT license
(see `LICENSE`). [LC-04][LC-24]

This file must be updated whenever a dependency is added, upgraded, or
removed (PR checklist item). [LC-05][B-05]

---

## libarchive

- **Used for**: reading/writing zip, 7z, tar.gz (and, in
  `PERMISSIVE_ONLY_BUILD` configurations, rar) archives. [LC-14]
- **License**: BSD 2-Clause (New BSD) — see individual file headers in the
  vendored source; a copy of the license is included by the upstream project.
- **Source**: https://github.com/libarchive/libarchive
- **Vendoring method**: built from an official release tarball via
  `Scripts/build-libarchive.sh` into a static library under
  `ThirdParty/libarchive/`. qooLibrary does **not** link against the system
  `libarchive.dylib`. [LC-15][B-02]
- **Modifications**: none. Unmodified upstream source.

## UnRAR

- **Version**: 7.2.7 (source).
- **Used for**: reading `.rar`/`.cbr` archives in the default (non-permissive)
  build configuration. [LC-11][AR-01b]
- **License**: RARLAB's UnRAR source license, which is **not** MIT/BSD-style.
  Full text: `ThirdParty/unrar/license.txt`. [LC-24] Key terms:
  - Free to use in any software that reads RAR archives, at no charge.
  - **Must not** be used to develop a RAR (WinRAR) compatible archiver, and
    must not be used to re-create the (proprietary) RAR compression
    algorithm. [LC-26]
  - Any redistribution (modified or not) must retain the license paragraph
    quoted above, both in the license/documentation and in the source code
    comments of the resulting package. `Sources/QooUnrarBridge/*.mm`/`*.h`
    carry this notice at the top of each file. [B-04]
- **Source**: https://www.rarlab.com/rar_add.htm ("UnRAR source")
- **Vendoring method**: built from the official source tarball via
  `Scripts/build-unrar.sh` into a static library under `ThirdParty/unrar/`
  (git-ignored, regenerated by the script — not committed). Two headers
  (`raros.hpp`, `dll.hpp`) are copied unmodified into
  `Sources/QooUnrarBridge/` because the Objective-C++ bridge needs them at
  compile time; they are private to that target and never exposed to Swift.
- **Modifications**: none. Unmodified upstream source.
- **Isolation**: all calls into UnRAR are confined to a single
  Objective-C++ file, `Sources/QooUnrarBridge/QooUnrarBridge.mm`, per the
  01_プロジェクト構成とビルド.md B-03 design decision (build stability over
  direct C++ interop from Swift). Swift only ever sees the plain C API in
  `Sources/QooUnrarBridge/include/QooUnrarBridge.h`. [B-03]
- **`PERMISSIVE_ONLY_BUILD`**: `PERMISSIVE_ONLY_BUILD=1 swift build` omits
  the `QooUnrarBridge` target (and the `unrarBinary` binary target) from
  `Package.swift` entirely, falling back to libarchive's own RAR reader for
  `.rar`/`.cbr` files. This build mode does not require
  `Scripts/build-unrar.sh` to have been run, or `ThirdParty/unrar/` to
  exist at all. Coverage is reduced — see `Spikes/README.md` (T-12) for a
  measured comparison. [LC-12][LC-13]

## Adding a new dependency

Before adding any third-party dependency, confirm its license is compatible
with permissive redistribution (MIT/BSD/Apache-2.0/zlib-class licenses are
preferred; UnRAR is a deliberate, isolated exception — see above). Then:

1. Vendor the unmodified source under `ThirdParty/<name>/`.
2. Add a section to this file following the format above.
3. If the dependency is required for the default build, also update
   `README.md`'s build instructions.
