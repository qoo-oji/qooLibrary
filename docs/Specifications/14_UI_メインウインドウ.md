#### よく使う項目グループ [HG-01〜HG-10、ユーザー要望]

Finder のサイドバー「よく使う項目」にあたるグループを、ボリュームとテンポラリの
間に置く。並べられる場所と既定は **`FavoriteLocations` が唯一の出どころ**
（`Sources/qooLibraryApp/MainWindow/FavoriteLocations.swift`）。

| # | 要件 |
|---|---|
| HG-01 | 並べられるのは アプリケーション（`/Applications`）／ホーム／デスクトップ／書類／ダウンロード／ムービー／ミュージック／ピクチャ の 8 つ。**順序はこの並びで固定**（並べ替えは提供しない——位置が変わらなければ覚えた場所で押せる） |
| HG-02 | **既定で表示するのは アプリケーション・ホーム・デスクトップ・ダウンロード の 4 つ**［ユーザー指定］。残りは環境設定「表示」タブの「「よく使う項目」に表示」で切り替える |
| HG-03 | 表示・非表示は**項目ごとに 1 つのキー**（`qoo.favorites.visible.<rawValue>`）で持つ。配列で持つと「まだ設定していない」と「全部消した」を区別できず、後から候補を増やしたときに既存の利用者へ出すかどうかも決められない |
| HG-04 | 存在しないフォルダは出さない（`~/Sites` のように既定では作られないものがある）。**アクセス権の有無では落とさない**——落とすと許可を与える入口が消える |
| HG-05 | 表示名は文字列カタログから引く（`menu.go.*`）。訳語は Apple の一次情報（`/System/Library/CoreServices/SystemFolderLocalizations`）から写す。**`localizedName` は使わない**——`Bundle.main.preferredLocalizations` に固定され、アプリ内の表示言語切替に追従しない [実測] |
| HG-06 | アイコンは `FileIconProvider`（Finder と同一）。未許可でも正しく取れる [実測] |
| HG-07 | 行を押したとき、未許可なら**その場で許可パネル**を出してから移動する（`StandardLocationOpener`）。展開して「アクセス権がありません」になった場合も、そのボタンからその場で求める——環境設定へ誘導する他のグループとはここだけ扱いが違う［ユーザー判断: 明示的な要求の直後だから］ |
| HG-08 | 入口は `NavigationRoot.favorites`。⌘↑ は**実ホームで止まる**（ダウンロードからホームへは上がれる）[ユーザー判断]。`/Applications` のように実ホーム配下でない項目には天井を設けない |
| HG-09 | これらの行では、フォルダ自体を作り替える操作（名前を変更・複製・ゴミ箱・圧縮・エイリアス）を出さない [ユーザー判断、`FolderTreeRowContext.allowsStructuralOperations`]。配下の通常フォルダには従来どおり全項目が出る |
| HG-10 | 行への D&D は許可する（書き込むのは「そのフォルダの中へ」なので、標準の場所自体は壊れない）[ユーザー判断] |

**サンドボックス下の到達性**（実アプリと同一 entitlement のプローブで実測。
根拠の表は `qooLibrary.entitlements` のコメント）:

| 項目 | 素の到達性 | 対応 |
|---|---|---|
| アプリケーション（`/Applications`） | ○ | 素のサンドボックスで読める |
| ダウンロード／ムービー／ミュージック／ピクチャ | ○ | `com.apple.security.files.downloads.*` と `assets.*` で素通り |
| デスクトップ／書類 | ✗（TCC） | そのパスへの許可が要る。`/` を許可していても毎回 TCC が出る |
| ホーム | ✗ | `/` への許可で足りる |

#### 起動時に開くフォルダは「グループ直下に見えているもの」から選ぶ [ユーザー判断]

| グループ | 選べる範囲 |
|---|---|
| ボリューム | 任意のフォルダ（`NSOpenPanel`＋専用のブックマーク） |
| よく使う項目 | **いま表示している項目**のみ |
| テンポラリ／ライブラリ | 登録済みのフォルダ |

選んだ場所へ届かない（環境設定で隠した・フォルダが消えた・読めない）ときは
**ボリューム経由のホームへ落とす**［ユーザー判断］。判定は `access(2)` 1 回で、
よく使う項目はすべて起動ボリューム上なので待ちが青天井になる I/O ではない。

`StartupFolderKind.favorite` の `rawValue` が `"virtualHome"` なのは歴史的な事情
（以前この値は「ホーム」固定を意味した）。既存の設定はそのまま
「よく使う項目 ＞ ホーム」として引き継がれる。

#### パッケージは 1 つの項目として扱う [PK-01〜PK-06、ユーザー要望]

`.app` をダブルクリックすると中へ入ってしまっていたのを、Finder と同じく
**起動する**ようにした。判定は `URLResourceKey.isPackageKey`——`.app` だけでなく
`.photoslibrary`／`.rtfd`／`.bundle` なども対象［ユーザー判断: パッケージ全般］。

| # | 要件 |
|---|---|
| PK-01 | ダブルクリック／Enter で**開く（起動する）**。中へは入らない |
| PK-02 | 中を見るのはコンテキストメニュー「パッケージの内容を表示」から（訳語は Finder の実文言 `LocalizableMerged.strings` の `N158` から写した） |
| PK-03 | **フォルダツリーに出さない。** `/Applications` を展開すると素のフォルダだけが並ぶ（[実測] 45 件中 41 件がパッケージ） |
| PK-04 | 種類は実際の種別（`.app` なら「アプリケーション」）。「フォルダ」とは答えない |
| PK-05 | 「フォルダを上にまとめる」[LV-03] ではファイル扱い。ドロップ先にもしない |
| PK-06 | 再帰検索は**中へ降りない**（`.app` 1 つで数千件あり、降りると結果が中身で埋まる）。パッケージ自身は結果に含める |

**実体がディレクトリであること自体は隠さない。** `FolderEntry.isDirectory` は
真のままで、UI の分岐は `isNavigableFolder`（`isDirectory && !isPackage`）を見る。
サイズ欄のように「実体がディレクトリか」を知りたい箇所は `isDirectory` を使う
——ここを潰すと、ディレクトリの `fileSize` が `nil` であるために
**アプリのサイズが「0 KB」と表示される**（実機検証で発見）。

副次的に、写真・ミュージックライブラリ（`.photoslibrary` 等）の中へ降りなくなる
ので、そこで出ていた TCC の許可ダイアログも止まる。

**三角マークの判定もこれに揃える** [`DirectoryProbe.hasSubdirectory(countingPackages:)`]
——ツリーに出さないものを理由に三角を出すと「開いても何も無い」嘘になる。
同じ理由で **`UF_HIDDEN`（`chflags hidden`）が立った項目も数えない**
[ユーザー報告で発見]: 名前が `.` で始まらないので `readdir` の名前判定では
弾けないが、Finder も `.skipsHiddenFiles` も隠すため、数えると
「一覧には何も出ないのに三角だけがある」状態になる。

#### 行の識別子は「正規化パス＋枝」[実機検証で発見・修正]

**同じ実フォルダが 2 つの枝に同時に現れる。** `~/Downloads` は「よく使う項目」の
行であると同時に、Macintosh HD → Users → … と辿った先にもある。以前はパス文字列
だけを鍵にしていたため、片方を展開するともう片方も開き、選択のハイライトが 2 か所に
出て、`scrollTo` がどちらへ飛ぶか決まらなかった——最後のものは「起動時に
『よく使う項目』の行をフォーカスする」を直接壊す。

`FolderTreeSelection`（url ＋ branch、同一性は**正規化パスと
`FolderTreeBranch.identityKey`**）を選択・展開・可視判定・スクロールのすべての
鍵にする。`URL` の等価判定は末尾スラッシュや `isDirectory` フラグまで見るので
同一性には使わない。枝の同一性に `rootURL` を含めないのも同じ理由
（登録 ID だけで一意に決まる）。

**ライブラリとテンポラリは同一性の上では区別しない**（`registered:<id>` に畳む）。
`NavigationRoot` は種別を持たないので、選択を組み立てる側は登録一覧を引いて
種別を決めるしかない——その一覧は非同期に読み込まれるため、**起動直後は空で、
テンポラリをライブラリと取り違える**。取り違えても登録 ID は同じなので、
畳んでおけば行と選択が一致する（登録 ID は種別をまたいで一意）。
**一覧が揃ったあとに選択を組み直す、という対処を採ってはいけない**——
そのメソッドは `await` を挟むので、あとで読む `selectedURL` は 1 世代古い値に
なり得て、`.onChange(of: listSelection)` がユーザー操作と区別できずに発火し、
**起動時フォルダを開いた直後にそれを捨てて古い場所へ戻す**（実機検証で踏んだ）。

**登録フォルダでも同じ形が元からあった**（登録したフォルダはボリュームを辿っても
到達できる）——「よく使う項目」の追加で確実に起こるようになったので直した。

#### 起動直後の自動展開は「材料」と「行き先」が揃ってから

`FolderTreePane` は次の 2 つが揃った時点で**1 回だけ**自動展開する:

- `treeDataLoaded`: ボリューム・ホーム・登録フォルダの一覧を読み終えた
- `startupFolderResolved`: 「起動時に開くフォルダ」の解決が終わった
  （`MainWindowView`）

**待たないと、解決前の暫定の行き先に対して展開が走り、`expandedNodeIDs` は減らない
のでその展開が残る**——ユーザー報告「テンポラリフォルダを指定しているのに、起動すると
Macintosh HD がホームフォルダまで展開される」がこの形だった。

以前は「上書きの見込みがあるか」を `UserDefaults` から事前に推測していたが、
`.home` を除外していたため **起動時フォルダを「ホーム」にすると仮想ホーム（`Data`）が
開いていた**［実機検証で発見］。`TabTarget.home` は `WindowState.init` で評価され、
その時点では `VolumeAccessStore.loadAndActivateAll()` がまだ終わっていないため
`defaultHome` が「実ホームを読めない」と判断してしまう。**解決を必ず通す**ように
して直した。

#### グループの開閉は永続化する [ユーザー判断]

4 グループそれぞれの開閉を `UserDefaults`（`qoo.folderTree.expanded.*`、既定はすべて
開）に覚える。**`@AppStorage` は使わない**——これらは「行を描くかどうか」の `if` 条件に
使うため、その形で読むと Observation が無限に再評価してハングする [1-9 で実際に踏んだ]。
初期値だけ素の値として読み、変更時に明示的に書き戻す一方向の同期にする。

**覚えるのは見出しのクリックだけ。** 自動展開（`revealSelectionIfNeeded`）は
`@State` を直接動かす——自動で開いたものまで覚えると、利用者が畳んだ意図を
アプリ側が黙って上書きすることになる。

### 下半分: ラベルフィルタ

```swift
// 実装は `QooApplication/LabelFilterModel.swift`（**アプリ層に置く**——UI に
// 置くと自動テストから触れない。SwiftUI には依存しない）。
@MainActor @Observable public final class LabelFilterModel {
    public private(set) var library: LibrarySummary?          // nil なら出さない [LF-01]
    public private(set) var groups: [LabelGroupSummary]       // ラベル 0 件は除く [LF-02]
    public private(set) var labels: [LabelGroupID: [LabelSummary]]
    public private(set) var selection: [LabelGroupID: Set<LabelID>]  // ウインドウ固有 [ST-21][LF-06]
    public var ratingFilter: FileQuery.RatingFilter?          // [RT-01〜03]
    public private(set) var matchedCount: Int?                // ライブラリ全体の該当数 [LF-11]
    public private(set) var totalCount: Int?                  // 分母 [LF-11]
    public private(set) var allowedChildNames: Set<String>?   // 中央ペインが残す名前 [VM-02]
    public private(set) var revision: Int                     // 再計算の合図

    public func toggle(_ label: LabelSummary)
    public func clearAll()                                    // [LF-07] ⇧⌘K。評価も落とす
    public func visibleLabels(in: LabelGroupSummary) -> [LabelSummary]   // [PN-02][PN-03][PN-06]
    public func load(registrationUUID: UUID?, services: LibraryServices) async
    public func refreshResults(folderRelativePath: String?, services: LibraryServices) async
    public func deepMatches(_ urls: [URL], libraryRootPath: String,
                            services: LibraryServices) async -> Set<URL>?  // [LF-14]
}
```

**中央ペインへは「DB の一覧を描く」のではなく「実体の一覧を絞る」形で効かせる。**
フォルダ表示モードではすべてのファイル操作が可能でなければならず [VM-03]、フィルタが
全 OFF なら DB に載っていないもの（対象拡張子以外）も従来どおり見える必要がある
[VM-01] ため。絞り込みの入口は 2 つ:

| 場面 | 使うもの | なぜ分かれるか |
|---|---|---|
| 通常の一覧 | `allowedChildNames`（直下の名前の集合）| 1 度の問い合わせで「該当ファイル」と「該当を配下に持つフォルダ」が両方得られる [VM-02] |
| 再帰検索の結果 | `deepMatches`（URL ごとに照合）| 深い階層の該当は**直下フォルダの名前へ畳まれて**集合に入るので、名前で突き合わせると同じフォルダの非該当ファイルまで通る [LF-14] |

**`nil` は「絞らない」**。空集合（＝何も残さない）と取り違えると一覧が黙って空になる
ので、問い合わせに失敗したときも `nil` に倒す——件数だけ伏せる。

#### 実装状況（2-10 の第 1 段、2026-08）

| 項目 | 状態 |

#### 構成

```
InspectorRatingSection（描くだけ）
   └ RatingEditorModel（QooApplication・判定と読み込み）
        └ LibraryServices.fileRow(at:in:) / setRating / filesInSameSeries
             └ ManagedFileRepository
```

`LabelFilterModel` と同じ分け方で、判定を `QooApplication` に置く——アプリターゲットのコードは `swift test` から触れないため、RA-02・RA-07・「DB に行が無いとき」を自動テストで固定できなくなる。

#### 決めたこと

| 論点 | 決定 |
|---|---|
| DB 行の引き当て | **`FileIdentity`（`library.volumeUUID` ＋ inode）で引く** [ID-02]。`relativePath` の照合にすると、綴り（NFD/NFC・大小文字）が 1 文字食い違った瞬間に黙って空振りする経路を新たに作ることになる（差分スキャンで実際に踏んだ形、10章 §10.6）|
| ライブラリの外 | 評価欄ごと出さない [LF-01 と同じ判断]。ボリューム経由で見ているだけのフォルダに評価の枠が出ると、何に対する評価なのか読み取れない |
| ライブラリの中だが DB に行が無い | **無効の星 ＋ 理由**［ユーザー判断］。黙って消すと「星を付けられない」のか「壊れている」のか区別が付かない |
| オフラインのライブラリ | **評価できる。** DB しか触らないので、実体の有無に関わらない（「ライブラリ機能を無効にする」で同じ判断をしている）|
| RA-05 の見せ方 | **確認ダイアログではなくボタンの文言**［設計判断］。RA-05 が求めているのは「対象件数を実行前に表示する」ことで、ダイアログとは書いていない。⌘Z で戻せる操作に毎回 1 枚挟むと、本当に見てほしいときの 1 枚まで読み飛ばされる（走査結果の提示で同じ判断をしている）|
| RA-04 の対象 | `.trashed` **だけ**を除く。孤立・オフラインは含める——外付けを抜いているあいだに全巻へ適用したら挿し直したときだけ 1 冊違う、という形のほうが驚きが大きい [ID-08] |
| 照合の鍵 | `seriesName` ではなく正規化済みの `seriesKey`（索引 `mf_lib_series`）。呼び出し側にシリーズ名を渡させると正規化の責務が移り、表記ゆれのある巻が**黙って対象から漏れる**——漏れたことは件数を数えても分からない |

#### Undo [RA-06]

**このコードベースで最初の「DB 操作の Undo」**（ロードマップ上は 2-15）。要件が「1 つの Undo 単位」と名指ししている以上、後から被せる形にはできないため評価だけ先に作った。

- 単発の星付けと全巻適用は**同じ `SetRatingCommand`** を通す。件数が違うだけの同じ操作に独立した経路を 2 つ作らない。
- **変更前の値は 1 件ずつ持つ。** 全巻の元の評価はばらばらでありうるので、一律に 0 へ戻すと ⌘Z が元の評価を破壊する——しかも「戻した」ように見えるので気づきにくい。
- 書き戻しは変更前の値でまとめる（星は 6 通りなので最大 6 回の書き込み）。1 つのトランザクションではないため、途中で失敗したら `.partial` でどこまで戻せたかを伝える [ER-13]。
- ⌘Z / ⇧⌘Z はこの View を通らずに DB を書き換えるので、インスペクタの `.task(id:)` は **`CommandStack.operationHistory.count`** も鍵に含める（`record` が run / undo / redo のいずれでも 1 件増やす）。

#### 消えないことの担保

| 経路 | 担保 |
|---|---|
| 再スキャン | `updateInPlace` の SQL に `rating` 列が無い（回帰テスト `survivesRescan`、変異検証済み）|
| JSON バックアップ | `rating` は `regenerableColumns` に**無い**＝再生成不可能データとして書き出される [MG-22] |
