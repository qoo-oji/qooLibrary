## 9.2 文字化け対策 [AR-02〜AR-04]

対象は zip / 7z のみ。RAR はアーカイブ側がエンコーディング情報を持つため対象外 [AR-03][C-06]。

```swift
public enum ArchiveNameEncodingHeuristic {
    public struct Candidate: Sendable {
        public let encoding: String.Encoding      // .utf8 / .shiftJIS (CP932)
        public let score: Double                  // 0.0〜1.0
        public let decodedSamples: [String]
    }
    /// UTF-8 フラグ未設定時の推定 [AR-02]
    public static func evaluate(rawNames: [Data]) -> [Candidate]
}
```

```pseudo
evaluate(rawNames):
    # ① UTF-8 として妥当にデコードできるか
    utf8Score = 妥当にデコードできた件数 / 全件
              - (U+FFFD や制御文字の出現率 × ペナルティ)
    # ② CP932 としてデコードした結果の妥当性
    cp932Score = デコード成功率
               + (日本語文字クラス〔ひらがな・カタカナ・CJK〕の出現率 × ボーナス)
               - (機種依存の未定義領域の出現率 × ペナルティ)
    # ③ よくある化けパターン（"ﾁ" "�" "?" の連続、Latin-1 由来のモジバケ）を減点
    return [utf8, cp932].sorted(byScoreDesc)
```

| # | 要件 |
|---|---|
| EN-01 | Keka の実装を参考にする [AR-02]。判定結果は展開前にプレビューし、ユーザーが手動でエンコーディングを変更できる [AR-04] |
| EN-02 | プレビューは先頭 20 エントリを両エンコーディングで並べて表示する |

### ステージング [EX-01〜EX-04]

```swift
public struct ExtractOptions: Sendable {
    public var destination: URL
    public var encoding: String.Encoding?
    public var followSymlinks: Bool = false          // [EX-12]
    public var limits: ExtractLimits = .default      // [EX-21]
}

public struct ExtractResult: Sendable {
    public let extractedCount: Int
    public let rejected: [(entry: String, reason: RejectionReason)]  // [EX-14]
    public let renamedForCaseCollision: [(from: String, to: String)] // [EX-15]
    public let totalBytesWritten: Int64
}
```

```pseudo
extract(archive, options):
    staging = appContainer/staging/<uuid>/          # [EX-01][EX-03]
    defer { removeRecursively(staging) }

    # 事前チェック [EX-23]
    declared = 宣言された非圧縮サイズの合計
    if freeSpace(options.destination) < declared + AppLimits.freeSpaceMargin:
        throw .insufficientFreeSpace

    written = 0; entryCount = 0
    for entry in archive.entries:
        entryCount += 1
        if entryCount > limits.maxEntries: throw .tooManyEntries        # [EX-21]

        # ── パストラバーサル対策 ──
        name = normalize(entry.pathname)
        if name.isEmpty                       : reject(.emptyName)      # [EX-10]
        if name.hasPrefix("/")                : reject(.absolutePath)
        if name.components.contains("..")     : reject(.parentTraversal)
        if name.containsNULOrControlChars     : reject(.invalidCharacters)
        if entry.isSymlink and !followSymlinks: reject(.symlinkSkipped)  # [EX-12]
        if entry.isHardlink || isDevice || isFIFO: reject(.specialEntry) # [EX-13]

        target = (staging / name).standardizedFileURL.resolvingSymlinksInPath()
        if !target.path.hasPrefix(staging.resolved.path + "/"):
            reject(.escapesDestination)                                  # [EX-11]

        # 大文字小文字のみ異なるエントリの衝突 [EX-15]
        if caseInsensitiveSeen.contains(target.lowercased):
            target = nextAvailableName(target); record(renamed)

        # ── 展開爆弾対策 ──
        stream = entry.dataStream
        while chunk = stream.next():
            written += chunk.count
            if written > limits.maxUncompressedBytes: throw .expansionLimitExceeded  # [EX-20][EX-21]
            ratio = Double(written) / Double(archive.compressedSize)
            if ratio > limits.ratioAbort:  throw .compressionRatioExceeded
            if ratio > limits.ratioWarn:   warnOnce()
            write(chunk, to: target)
        if Task.isCancelled: throw CancellationError()                   # [EX-24]

    # 最終位置へ移送。FileOperationService 経由 + 台帳登録 [EX-04]
    try await fileOps.promoteFromStaging(staging, to: options.destination)
```

| # | 要件 |
|---|---|
| EXI-01 | 宣言された非圧縮サイズを信用しない。**書き出し中の実バイト数**で判定する [EX-20] |
| EXI-02 | 上限は環境設定で変更できる。中断時は理由と該当する上限を明示する [EX-22] |
| EXI-03 | 拒否・スキップしたエントリは件数と理由を展開結果に表示する [EX-14][RB-01] |
| EXI-04 | キャンセル時はステージングごと破棄する [EX-24] |

| # | メニュー | 挙動 |
|---|---|---|

| AR-11 | 圧縮… | ファイル名・形式・保存先を指定するダイアログ。既定値は AR-10 と同じ |
| AR-20 | ここに展開 | カレントフォルダへ展開。複数選択時も同じ |
| AR-21 | （名前）に展開 | 圧縮ファイル名のフォルダを作って展開。複数選択時はファイルごと |
| AR-22 | 展開… | 展開先を選ぶダイアログ。複数選択時はまとめて |
| AR-23 | — | 複数選択時の AR-21 の表記は「それぞれのフォルダに展開」 |

**実装状況（1-12 環境設定「圧縮／展開」タブ）**: 圧縮形式（zip/7z）・zip の圧縮レベル・7z のコーデック（PPMd/bzip2/deflate/copy）・zip の暗号化方式（なし/Traditional/AES-128/AES-256）は環境設定の既定値として設定可能にした。AR-11「圧縮…」ダイアログは環境設定の既定形式に従うのみで、**操作のたびに形式を選び直す UI は未実装**（この表の「ファイル名・形式・保存先を指定する」の「形式」部分は環境設定側の既定を使う設計に簡略化している）。7z は libarchive の書き込み側に暗号化オプションが存在しないため、暗号化は zip 選択時のみ有効。パスワード文字列自体は環境設定に保存せず、暗号化が有効なときは圧縮のたびに `ArchivePasswordSheet` で入力させる。展開の安全上限（`ExtractLimits`）も同タブで調整可能。詳細は CLAUDE.md 参照。

### 圧縮エントリ名の Unicode 正規化 [設計判断][AR-10][AR-11]

macOS の Foundation API（`FileManager`/`URL`）はファイル名を NFD（濁点・半濁点等が
結合文字に分解された形）で返すことが多い。これをそのまま zip のエントリ名として
書き込むと、NFC を前提とする Windows 側の展開ツールで文字化けしたり、見た目は同じ
なのにバイト列が異なる別名として扱われたりする（Mac 製 zip アーカイバでよく知られた
問題）。**圧縮時は各エントリ名を NFC 正規化してから書き込み、UTF-8 フラグも明示的に
立てる**（Keka 等と同じ方式、EN-01 参照）。N-01〜N-03 のラベル照合用正規化
（`TextNormalizer`、3章）とは目的も適用箇所も別物で、両者を混同しない。

### サムネイル表示の一括制御 [DS-01〜DS-07]

| # | 要件 |
|---|---|
| DS2-01 | 一括トグル。無効時は汎用アイコンに切り替わる [DS-01] |
| DS2-02 | メニューバーとキーバインド（既定 `⌃⌘I`）から即時切替 [DS-02] |
| DS2-03 | 全ウインドウ・全タブに即座に反映（アプリ全体の状態）[DS-03] |
| DS2-04 | ライブラリ／テンポラリフォルダごとに**強制非表示**の設定を持つ（`Library.thumbnailsAlwaysHidden`）[DS-04] |
| DS2-05 | **非表示中は生成・キャッシュを行わない**。再表示時に生成する [DS-05] |
| DS2-06 | 右ペインのカバー表示 [CV-01] と Quick Look の**独自カバー** [QL-03] も同じトグルに従う [DS-06] |
| DS2-07 | 現在の状態と、非表示になっている理由をステータスバーに示す [DS-07] |

**実効値の合成 [設計判断、ユーザー確認済み]**: 要件 DS-04 の文言は「ライブラリごとに
既定値を持てる」だが、**「入った時点で全体トグルの値を書き換える」形にはしない**
——全体トグルは DS-03 によりアプリ全体で共有される状態なので、あるウインドウが
ライブラリへ移動しただけで**他のウインドウの表示まで巻き添えで変わる**。
代わりに全体トグルとは独立した制約として持ち、

```
実効値（そのウインドウで隠すか） = 全体トグルが非表示 || 今いる登録フォルダが強制非表示
```

と合成する。要件が挙げる運用（「特定のライブラリだけ常に非表示にする」）はこれで
素直に満たせる。**合成に必要な「今どの登録フォルダの中にいるか」を知っているのは
UI 層だけ**（`NavigationRoot`、14章）なので、判定は UI 層に置き、
`ThumbnailService` が持つのは全体トグルの関門だけにする。

**DS2-07 の見せ方**: ステータスバーに常設のトグルボタンを置き、非表示のときだけ
強調する。ライブラリ側の強制非表示が効いている間は、全体トグルを反転しても
そのウインドウの見た目は変わらないためボタンを無効化し、ツールチップで
どのフォルダの設定によるものかを示す [ユーザー判断]。

**ネットワークボリュームとの関係（1-16b）**: サムネイル生成は**ファイル本体を
丸ごと読む**ため、ネットワークボリュームでは I/O 増幅の最大の発生源になる
（8章 NV-37）。File Provider 系クラウド（`~/Library/CloudStorage/`）では、
一括生成が**ユーザのストレージを全件ダウンロードさせる**（NV-73）。DS-04 の
「登録フォルダごとの強制非表示」はこの縮退の器としてそのまま使えるが、
**ネットワークボリュームで既定を非表示にすべきか、`AppLimits.Thumbnail.maxConcurrent`
をネットワークでは下げるべきか（NV-38）は 1-16b で決める。** →  8章 §8.11

### バックグラウンド動画サムネイル生成 [ユーザー要望、要件定義書には無い]

登録済みライブラリ／テンポラリフォルダ配下（サブフォルダを含む）の**動画**の
サムネイルを、アプリ起動中にバックグラウンドで先回り生成する
（`BackgroundThumbnailWarmer`）。生成そのものは `ThumbnailService` に委ねる
（同時実行スロット [PF-11]・動画のタイムアウト・キャッシュの鍵 [TH-08] が
そのまま効く）ため、掃引側が持つのは「何を・いつ・どの順で頼むか」だけ。

| 決めごと | 内容 |
|---|---|
| 実行時機 | **アプリ起動中のみ**。常駐ヘルパー（launchd エージェント等）は作らない [設計判断、ユーザー確認済み: app-scope の Security-Scoped Bookmark は作成したアプリ本体しか解決できず、別プロセスに持たせると権限管理が二重になる。起動直後に掃引を始めれば次回以降は差分だけになるため、終了中生成の利点はほぼ得られる] |
| 掃引の合図 | 起動時・登録フォルダの増減や DS-04 の切替等（`RegisteredFolderIndex.refresh()` に集約）・全体トグルの再表示（`ThumbnailVisibility.onGlobalVisibilityChanged`）・環境設定での有効化。合図は短く待ち合わせて 1 回にまとめる |
| 優先度 | 逐次 1 本（スロット 4 本のうち最大 1 本）＋ `.background`。UI のオンデマンド要求が常に勝つ |
| 形式単位のスキップ | 同じ拡張子が 1 度も成功しないまま 3 回失敗したら、そのセッションでは以降スキップ。**意図的に永続化しない** — QuickLook 拡張の有無を列挙する公開 API は無く、「次回起動時に再試行」が「対応する拡張をインストールしたら自動的に生成される」を検知コードなしで満たす最も堅い方法のため |
| 対象外 | ネットワークボリューム上の登録フォルダ [NV-37]・dataless なファイル [NV-73]・DS-04 強制非表示のフォルダ・全体トグル非表示中 [DS-05] |
| 無効化 | 環境設定「キャッシュ」タブのトグル（既定は有効）[ユーザー要望] |

`QLPreviewPanel` はレスポンダチェーンをたどって「制御するオブジェクト」を選ぶため、
SwiftUI のビュー階層には差し込み先が無い。`NSWindow.nextResponder` へ専用の
`NSResponder` を挿入して受け取る（`QuickLookPanelInstaller`）。この位置が実際に
採用されることは最小の AppKit アプリで実測確認済み（ファーストレスポンダが辞退した
場合に次に尋ねられる。ウインドウデリゲート・アプリデリゲートは尋ねられない）。

| # | 要件 |
|---|---|
| QL2-01 | pdf / epub / 画像 / 動画は標準 Quick Look に委譲する [QL-02] |
| QL2-02 | **対応アーカイブ全般（zip/cbz・7z/cb7・rar/cbr・tar.gz）とフォルダ**は独自プレビューに差し替える [QL-03][QL-08]。差し替え対象の判定は `PreviewableFileKind.needsCustomCoverPreview` 1 箇所に集約する [設計判断: 要件 QL-03 は `.cbz`/`.cbr`/`.cb7` のみを挙げるが、本アプリは `.zip` と `.cbz` を `ArchiveFormat` の同一値として扱い、アイコン表示のサムネイルも同じ経路で生成する。拡張子だけで Quick Look の挙動が変わるとアプリ内で説明のつかない不整合になるため対象を広げた。フォルダを含めることで、ブックフォルダ [QL-08] もフェーズ 2 の概念導入を待たずに満たせる] |
| QL2-03 | 独自プレビューはカバー画像 1 枚のみ。ページ送りを持たない [QL-04] |
| QL2-04 | カバー選択順は IV-02 / IV-03 に従う [QL-05]。解決は `CoverImageSourceResolver`（サムネイル生成と共有）に集約する |
| QL2-05 | タイトル・シリーズ名・巻数・評価・付与ラベル・ファイルサイズを併記 [QL-06]。**フェーズ 1 では QL2-08 の方式上パネルへ重ねられないため、ファイル名のみ（`previewItemTitle`）とする**。ラベル・評価が入るフェーズ 2 で「カバー＋メタデータを 1 枚に合成して渡す」か「独自パネルへ移行する」かを判断する |
| QL2-06 | 矢印キーで選択移動、プレビューが追従 [QL-07]。`previewPanel(_:handle:)` で受け、一覧の表示順に沿って選択を隣へ動かす（複数選択中の ← → はパネル自身が選択内の移動に使うため届かない＝ Finder と同じ） |
| QL2-07 | カバー未生成なら待たずプレースホルダを出し、非同期に差し替える [QL-09]。差し替え前は**元のファイル URL をそのまま渡す**ことで、標準 Quick Look のアーカイブ表示がプレースホルダとして機能する |
| QL2-08 | 実装は `QLPreviewingController`（App Extension）を使わず `QLPreviewPanel` で行う [設計判断: 拡張機能を追加せずに済み、公証なしの配布形態と相性が良い]。**独自プレビューは「中の先頭画像を実ファイルとして書き出し、その URL を `QLPreviewItem.previewItemURL` として渡す」方式**とする（`QuickLookCoverStore`）——`QLPreviewPanel` に項目ごとの独自ビューを差し込む API は存在しないことを SDK ヘッダで確認済み。書き出しは再エンコードせず原画像のバイト列そのものを使い、標準の画像プレビューが持つズーム・フルスクリーンをそのまま活かす |
| QL2-09 | 書き出したカバーはセッション限りのキャッシュとし、アプリ起動時に丸ごと捨てる（`SecureExtractor.cleanupResidualStaging()` と同じ方式）。1 セッション中の肥大を防ぐため合計サイズの上限を設け、古いものから削除する |
