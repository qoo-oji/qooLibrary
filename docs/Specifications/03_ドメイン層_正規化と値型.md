# 03. ドメイン層 — 文字列正規化と値型

対応要件: N-01〜N-04 / WS-01〜WS-07 / DB-03 / SR-06 / DU-03 / PT-04

## 3.1 正規化の 4 段階

ラベルの重複と検索の取りこぼしはすべてここで潰す。**正規化は 1 箇所にしか実装しない。**

| 段階 | 処理 | 根拠 |
|---|---|---|
| ① Unicode 正規化 | NFD → **NFC** | [N-01] macOS の FS が NFD で返すため |
| ② 幅の統一 | 全角英数字・記号 → 半角、全角スペース → 半角スペース | [N-02][SE-03] |
| ③ 空白の畳み込み | 連続する空白（半角・全角・タブ）→ 半角スペース 1 個、前後トリム | [WS-06][FF-14] |
| ④ ケース | ライブラリ設定に従い小文字化（既定：区別しない＝小文字化する） | [N-04] |

```swift
public struct NormalizationOptions: Sendable, Hashable {
    public var caseSensitive: Bool = false      // [N-04] 既定 false → 小文字化する
    public static let `default` = NormalizationOptions()
}

public enum TextNormalizer {
    /// 表示用。原文を保持する（正規化しない）。 [N-02][N-03]
    public static func display(_ s: String) -> String { s }

    /// ①②③（④は options 次第）を通した照合用文字列。
    public static func normalize(_ s: String, options: NormalizationOptions = .default) -> String

    /// ①②のみ。フィールド値の内部空白を保持したいときに使う。 [WS-05]
    public static func canonicalWidth(_ s: String) -> String

    /// 先頭・末尾の空白（半角・全角・タブ）を除去。 [FF-14][WS-05]
    public static func trimWhitespace(_ s: String) -> String

    /// 検索用。normalize の結果をさらにカナ統一（ひらがな→カタカナ）した文字列。 [DB-03][SR-06]
    public static func searchKey(_ s: String) -> String
}
```

### 実装上の注意

| # | 要件 |
|---|---|
| NM-01 | ②の全角→半角は `CFStringTransform(.fullwidthHalfwidth)` を使わず、**変換表を自前で持つ**。`CFStringTransform` は「ー」（長音）や半角カナまで変換してしまい、日本語タイトルを壊すため [設計判断] |
| NM-02 | 変換対象は `０-９` `Ａ-Ｚ` `ａ-ｚ` `！-～`（U+FF01〜U+FF5E）と `U+3000`（全角スペース）に限定する。半角カナ（U+FF61〜U+FF9F）は**変換しない** |
| NM-03 | 空白とみなす文字は `U+0020` `U+3000` `U+0009` `U+00A0`。改行はファイル名に現れないが、現れた場合は空白として扱う |
| NM-04 | `normalize` は純粋関数。同じ入力に対し常に同じ出力を返し、単体テストのカバレッジ 100% を必須とする [MT-01] |
| NM-05 | `normalize` の結果はキャッシュ可能。`ManagedFile.normalizedName` / `Label.normalizedName` はこの結果を保存したもの [DB-03] |
| NM-06 | ラベルの一意性判定は `(labelGroupID, normalize(name, options))` の組で行う。表示名は最初に登録された原文 [N-03] |

### 例

| 入力 | `normalize`（caseSensitive=false） |
|---|---|
| `佐藤秀峰`（NFD） | `佐藤秀峰`（NFC） |
| `ＡＢＣ　１２３` | `abc 123` |
| `  ブラック  ジャック  ` | `ブラック ジャック` |
| `Vol.１２` | `vol.12` |

## 3.2 弾力的空白（Elastic Whitespace）[WS-01〜WS-04]

フォーマット中のリテラル空白は「0 個以上の空白」にマッチする。

```swift
public enum Whitespace {
    /// フォーマット照合用: 空白 0 個以上にマッチする。 [WS-01]
    public static func matchesElastic(_ scalars: Substring) -> Int   // 消費した文字数を返す

    /// 巻数フォーマットの <space> 用: 空白 1 個以上を必須とする。 [WS-07][SE-23]
    public static func matchesRequired(_ scalars: Substring) -> Int? // nil = 不一致

    /// フォーマット定義の保存時正規化: 連続空白 → 半角 1 個。 [WS-03][WS-04]
    public static func normalizeLiteral(_ format: String) -> String
}
```

| # | 要件 |
|---|---|
| WSI-01 | `] @title` `]@title` `]　@title` は `normalizeLiteral` を通すといずれも `] @title` になる [WS-02] |
| WSI-02 | 保存時に正規化するため、テンプレート JSON に全角スペースが混入していても実害がない [OP-04][WS-04] |
| WSI-03 | 抽出したフィールド値は `trimWhitespace` のみを適用し、内部の空白は原文のまま保持する [WS-05] |

## 3.3 主要な値型

```swift
/// ボリューム内で一意なファイル識別子。DB の主たる同一性キー。 [ID-01]
public struct FileIdentity: Sendable, Hashable, Codable {
    public let volumeUUID: String
    public let inode: UInt64
}

/// 正規化済み文字列。生の String と取り違えないための型安全ラッパ。
public struct NormalizedString: Sendable, Hashable, Codable, CustomStringConvertible {
    public let raw: String          // 原文（表示用） [N-03]
    public let key: String          // 正規化済み（照合用）
    public init(_ raw: String, options: NormalizationOptions = .default)
    public var description: String { raw }
    public static func == (l: Self, r: Self) -> Bool { l.key == r.key }
    public func hash(into h: inout Hasher) { h.combine(key) }
}

/// 巻数の構造化表現。 [CR-20][SE-09][SE-10]
public struct VolumeValue: Sendable, Hashable, Codable {
    public enum Kind: String, Sendable, Codable { case numeric, ordinal, none }
    public let kind: Kind
    public let number: Double?      // .numeric のときの値（3.5 を許容）
    public let ordinalRank: Int?    // .ordinal のときのソート順序値 [SE-10]
    public let raw: String?         // 原文表記（"第01巻" "上巻"）
    public static let none = VolumeValue(kind: .none, number: nil, ordinalRank: nil, raw: nil)

    /// ソート用の単一キー。numeric < ordinal < none の順で安定させる。
    public var sortKey: Double {
        switch kind {
        case .numeric: return number ?? 0
        case .ordinal: return Double(ordinalRank ?? 0)
        case .none:    return .infinity
        }
    }
}
```

/// フォーマット照合の結果。 [9 章]
public struct ParseResult: Sendable {

    public let field: FieldRef
    public let range: Range<String.Index>  // 元のファイル名（保護復元後）における範囲

    case author
    case volume

## 3.4 ライブラリ設定の値型（永続化非依存）

`QooKit` 側でパーサが必要とする設定だけを切り出した DTO。SwiftData モデルから射影して渡す [A-01]。

```swift
public struct LibrarySettingsSnapshot: Sendable {
    public let libraryID: UUID
    public let displayName: String                    // @libraryname の照合値 [RW-04]
    public let libraryTypeName: String                // @librarytype の照合値 [RW-01]
    public let allLibraryTypeNames: [String]          // 型付き照合の列挙候補 [9.2.2]
    public let allLibraryDisplayNames: [String]
    public let targetExtensions: Set<String>
    public let imageExtensions: Set<String>           // [IF-02]
    public let delimiters: DelimiterSet                // [9.3]
    public let protectedTokens: [ProtectedToken]       // [9.2.3]
    public let filenameFormats: [CompiledFormat]       // 優先順 [FF-03]
    public let folderLevelFormats: [Int: CompiledFormat] // 階層 → フォーマット [AL-01]
    public let volumeFormats: [CompiledVolumePattern]  // 優先順 [SE-21]
    public let semanticBindings: [SemanticKeyword: UUID] // [RW-13]
    public let labelGroupIDsByIndex: [Int: UUID]
    public let normalization: NormalizationOptions
    public let seriesTitleCompositionFormat: String    // 既定 "@series @volume" [SE-33]
}

public enum SemanticKeyword: String, Sendable, Codable, CaseIterable {
    case series = "@series"
    case author = "@author"
    // 将来: circle / event / genre をここに足すだけでスキーマ変更不要 [RW-13]
}
```

| # | 要件 |
|---|---|
| VT-01 | `LibrarySettingsSnapshot` は **immutable な値型**。設定変更のたびに作り直し、パーサへ渡す。パーサ側は状態を持たない [A-01] |
| VT-02 | 生成コストを避けるため、`libraryID` + `settingsRevision`（Int）でキャッシュする。設定変更で revision を上げる |
| VT-03 | `CompiledFormat` / `CompiledVolumePattern` はコンパイル済み AST を含む。UI からの編集のたびに再コンパイルする [FF-06][HP-04] |
