## 16.2 ゴールデンテスト [MT-20〜MT-28]

**ファイル名パーサの正しさを担保する主要手段。**

### データセット形式 [MT-21]

`Tests/GoldenDataset/{public,private}/*.json`

```jsonc
{
  "datasetName": "general-comic-b-positive",
  "visibility": "public",                        // public | private [MT-28]
  "cases": [
    {
      "id": "gcb-001",
      "input": "[佐藤秀峰] ブラックジャックによろしく 第01巻",
      "context": {
        "template": "一般コミック(B)",             // テンプレート名 または settings 一式
        "folderPath": "佐藤秀峰/ブラックジャックによろしく"
      },
      "expected": {
        "matched": true,
        "formatIndex": 1,
        "fields": {
          "@labelgroup1": "佐藤秀峰",
          "@title": "ブラックジャックによろしく 第01巻"
        },
        "series": "ブラックジャックによろしく",
        "volume": { "kind": "numeric", "number": 1, "raw": "第01巻" },
        "labels": { "著者": ["佐藤秀峰"], "シリーズ": ["ブラックジャックによろしく"] }
      }
    },
    {
      "id": "gcb-neg-001",
      "input": "ブラックジャックによろしく - 佐藤秀峰",
      "context": { "template": "一般コミック(B)" },
      "expected": { "matched": false }            // 負例 [MT-23]
    }
  ]
}
```

| # | 要件 |
|---|---|
| GT-01 | 対象は ① ファイル名フォーマットのパーサ ② シリーズ抽出 ③ 巻数の正規化 ④ 保護文字列 ⑤ 変換リネームの出力 [MT-22] |
| GT-02 | プリセット 8 種それぞれについて正例・負例を最低 20 件ずつ [MT-23] |
| GT-03 | パーサ変更時は全件実行。差分が出たら「期待結果を更新する」か「実装を直す」かを明示的に判断する [MT-24] |
| GT-04 | 実運用で誤判定が見つかったら、**そのファイル名を必ずデータセットへ追加してから修正する** [MT-25] |
| GT-05 | 未解決一覧 [15.6] とペンディング一覧 [15.8] から、選択ファイル名をサンプルとしてエクスポートできる [MT-26] |
| GT-06 | サンプル収集は実装開始前から始められる。第 2 段階のパーサ実装に先行して着手する [MT-27][DP-09] |
| GT-07 | 実在の作品名・著者名を含むサンプルは `private/` に置き `.gitignore` する。CI は `public/` のみ実行 [MT-28][B-14] |

### 収集の導線

```swift
public protocol GoldenSampleExporting: Sendable {
    /// 選択したファイル名 + 現在の設定 + 実際の抽出結果を JSON 断片として書き出す。
    /// expected は現在の実装結果を初期値とし、人間が確認して確定させる。
    func exportSamples(_ files: [FileSnapshot],
                       libraryID: UUID,
                       visibility: DatasetVisibility) async throws -> URL
}
```

## 16.4 統合テスト

一時ディレクトリに擬似ライブラリを構築して実行する。

| シナリオ | 検証 |
|---|---|
| 初回フルスキャン | 1,000 件の擬似ファイルでラベルが期待どおり付与される [AT-02] |
| リネーム → 再計算 | 自動ラベルのみ更新され、手動ラベルが保護される [RC-01〜RC-05] |
| 自己変更の除外 | `FileOperationService` 経由のリネームで再スキャンが走らない [FO-11〜FO-13] |
| 無限リネームの防止 | 台帳を強制的に無効化しても、冪等性により停止する [FO-24][R-13] |
| アーカイブ往復 | `.qooarchive` への移動と復元で inode が維持され、ラベルが保たれる [FA-02][T-07] |
| サイドカー連動 | `covers/` の画像が連動移動・復元される [FA-14][FA-15] |
| ゴミ箱往復 | `.trashed` → 復元でラベルが完全に戻る [TR-04][TR-05] |
| オフライン | ボリューム未接続時に孤立判定が走らない [SB-05][ID-08][R-01] |
| 排他 | 一括処理中に別の一括処理が即座に拒否される [LK-14] |
| デッドロック | 2 つの複数フォルダ処理を同時起動しても停止しない [LK-13] |
| 移行 | v1 → v2（ダミー）でバックアップが作られ、失敗時は読み取り専用で起動する [MG-10][MG-11] |
| JSON 往復 | エクスポート → 新規ストアへインポート → 再スキャンで再生成不可能データが完全復元される [MG-23][MG-24][IE-16] |
| 展開セキュリティ | パストラバーサル・展開爆弾・シンボリックリンクの各攻撃サンプルを拒否する [EX-10〜EX-24] |
| 文字化け | CP932 の zip サンプルが正しく展開される [AR-02][T-06] |
| ペンディング | 3 種の理由が正しく分類され、変換リネーム後に「解決済み」へ遷移する [MV-14][CW-43] |
