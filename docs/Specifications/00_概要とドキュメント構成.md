## 0.1 本書の位置づけ

要件定義書 v2.8 の全要件（約 700 項目）を、**Swift / SwiftUI / SwiftData での実装に直接落とせる形**へ変換したもの。

- 要件定義書が「何を作るか（WHAT）」、本書が「どう作るか（HOW）」を担当する。
- 本書に登場するすべての設計判断は、根拠となる要件 ID を `[FO-01]` の形式で併記する。要件 ID を持たない設計判断には `[設計判断]` を付し、判断理由を明記する。
- 本書と要件定義書が矛盾した場合、**要件定義書が優先する**。本書を修正すること。

## 0.3 モジュール地図

```
qooLibrary/
├─ QooKit（Domain, Foundation のみに依存）          [A-01]
│   ├─ Normalization      文字列正規化・NormalizedString
│   ├─ Format             AST / Compiler / Matcher / ProtectedToken
│   ├─ Volume             巻数フォーマット・抽出・出力書式
│   ├─ Rename             自動リネーム・変換リネーム・一括リネーム（純粋関数）
│   ├─ Filter             ラベルフィルタの集合演算
│   └─ Model              永続化非依存の値型（LibrarySettings, LabelGroupSpec …）
│
├─ QooPersistence（SwiftData）                      [A-02]
│   ├─ Schema/V1          @Model 定義
│   ├─ Migration          VersionedSchema / MigrationPlan
│   ├─ Repository         *RepositoryProtocol とその SwiftData 実装
│   └─ Index              LabelIndex（ラベル→ファイルID 集合）
│
├─ QooInfrastructure
│   ├─ FileOps            FileOperationService / ExpectedChangeLedger
│   ├─ Archive            ArchiveBackend / LibarchiveBackend / UnrarBackend
│   ├─ Imaging            ThumbnailService / CoverImageResolver
│   ├─ Watch              FSEventsWatcher / VolumeMonitor
│   ├─ Scan               ScanEngine / IdentityResolver
│   └─ Diagnostics        FileLogger / DiagnosticsBundle
│
├─ QooApplication
│   ├─ Command            Command / CompositeCommand / CommandStack
│   ├─ Lock               LockManager
│   ├─ UseCase            *UseCase 群
│   └─ Notification       NotificationCenterStore（通知履歴）
│
└─ qooLibraryApp（SwiftUI）
    ├─ DesignSystem       トークン・共通コンポーネント
    ├─ MainWindow
    ├─ Windows            専用ウインドウ群
    └─ State              WindowState / SessionState
```

### 依存方向

```
qooLibraryApp → QooApplication → QooPersistence ─┐
                      ↓                          ├→ QooKit
                QooInfrastructure ───────────────┘
```

- `QooKit` は `Foundation` 以外に依存しない [A-01]。`SwiftData` / `AppKit` / `SwiftUI` を import してはならない。
- `QooPersistence` と `QooInfrastructure` は相互依存しない。両者の協調は `QooApplication` が行う。
- この依存方向は SwiftPM のターゲット定義で強制する（01 章 §1.3）。

## 0.4 命名規約

| 対象 | 規約 | 例 |
|---|---|---|
| プロトコル | 能力は `-ing` / `-able`、役割は `-Protocol` 接尾なし | `ArchiveExtracting`, `LibraryRepository` |
| SwiftData モデル | 名詞、`@Model final class` | `ManagedFile` |
| 値型 | 名詞、`struct` | `VolumeValue`, `ParseResult` |
| ユースケース | `<動詞><対象>UseCase` | `ApplyAutoLabelsUseCase` |
| コマンド | `<動詞><対象>Command` | `MoveFilesCommand` |
| SwiftUI View | `<対象>View` / `<対象>Pane` / `<対象>Window` | `LabelFilterPane` |
| エラー | `<領域>Error` | `FormatCompileError` |
| 定数 | `AppLimits` / `AppDefaults` に集約 [MT-03] | `AppLimits.maxLabelGroups` |

- 要件 ID をコード中のコメントに残す。特に制約系（`FO-01`, `MG-01`, `LK-13` 等）は該当箇所に `// [FO-01]` を付す。
- 型名・変数名は英語、コメントとログメッセージは日本語を可とする。ユーザー向け文字列は String Catalog へ [UI-11]。

## 0.5 並行性モデル

| 領域 | 実行コンテキスト |
|---|---|
| SwiftUI View / ViewModel | `@MainActor` |
| `mainContext` を触る処理 | `@MainActor` [ST-02] |
| スキャン・サムネイル生成・一括処理・JSON 入出力 | `@ModelActor` の専用アクター [ST-04] |
| `FileOperationService` | `actor`（直列化） |
| `ExpectedChangeLedger` | `actor` |
| `LockManager` | `actor`、アプリ単一 [LK-11] |
| FSEvents コールバック | 専用 `DispatchQueue` → `AsyncStream` へ橋渡し |

- Swift 6 言語モード、`StrictConcurrency` を有効にする [設計判断: データ競合をコンパイル時に潰すため]。
- コンテキストをまたぐ受け渡しは `PersistentIdentifier` のみ [ST-06]。`@Model` オブジェクトを `Sendable` として渡さない。

## 0.6 本書で用いる記法

- Swift コードブロックは**実装の骨格**であり、そのままコンパイルは通らない場合がある（省略記号 `…` を含む）。シグネチャと制御構造は仕様として拘束力を持つ。
- 擬似コードブロックは `pseudo` 言語タグを付す。アルゴリズムの手順を仕様として拘束する。
- `[XX-00]` は要件定義書の要件 ID。`[設計判断]` は本書で新たに決めた事項。
- 「必須」「〜してはならない」は MUST、「望ましい」は SHOULD の意味で用いる。
