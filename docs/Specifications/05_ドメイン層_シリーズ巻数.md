# 05. ドメイン層 — 巻数フォーマットとシリーズ抽出

対応要件: SE-01〜SE-33 / CR-20〜CR-25 / RW-06〜RW-10 / 11.3 節

---

## 5.1 巻数フォーマットの記法 [10.2 節]

**記法は正規表現**（2026-08 の仕様変更）。以前は `??`（数字）と `<space>`（空白
1 個以上）という独自のメタ記号だったが、`vol` / `Vol` / `VOL` / `volume` の揺れを
1 本で書けず、既定セットが 19 本に膨れていた。旧記法からの変換は
`LegacyVolumeNotation`（DB の移行と JSON バックアップの取り込みが**同じ関数**を使う）。

| 決めごと | 内容 |
|---|---|
| エンジン | **ICU（`NSRegularExpression`）**。Swift 標準の `Regex` は同じ病的パターンで **1,500 倍遅く**、打ち切る手段も無い [実測] |
| 照合の対象 | **全角を半角へ畳み、NFC へ合成した射影**（`FoldedSubject`）。`[0-9]` だけで全角数字にも当たり、`(?i:vol)` は `ｖｏｌ` にも当たる |
| 巻数の値 | `(?<volume>…)` があればそれ、無ければ**唯一のキャプチャグループ**。0 個、または名前無しで 2 個以上なら保存時にエラー |
| `raw` | **必ず原文から取る**。全角や NFD の表記を失わない |
| 種別 | `volume`（巻数を取り出す）／ `separator`（シリーズ名を切るだけで巻数を持たない） |

**照合を畳んだ射影に対して行うので、`[０-９]` のような全角の文字クラスは決して
一致しない。**設定画面はこれを警告する。

### 種別 — 序列巻数の廃止

以前は「序列巻数」（`上巻` = 1, `下巻` = 3 のように順序値 `ordinalRank` を持つ
巻数）という種別があったが、**2026-08 の仕様変更で廃止した**［ユーザー判断］。
`上巻` のような表記は巻数ではなく「シリーズ名を切るための区切り」として扱う。

- `VolumeValue.Kind` は `.numeric` と `.none` の 2 つになった
- 巻数のソートは `numeric < none` の 2 段
- `VolumeOutputStyle.ordinalTemplate` は出力すべき値が無くなったので削除
- **種別はキャプチャの有無では判定できない**——`総集編([0-9]+)` は区切り専用なのに
  キャプチャを持つ。明示的に持つ

```swift
public enum VolumePatternKind: String, Sendable, Codable, Hashable, CaseIterable {
    case volume        // 巻数を取り出す
    case separator     // シリーズ名を切るだけ
}

public struct VolumePattern: Sendable, Hashable, Codable, Identifiable {
    public let id: UUID
    public var source: String          // 正規表現
    public var isEnabled: Bool
    public var priority: Int           // 登録順＝同長のときの決着に使う [SE-21]
    public var kind: VolumePatternKind
}

public struct CompiledVolumePattern: Sendable {
    public let id: UUID
    public let source: String
    public let kind: VolumePatternKind
    public let priority: Int
    let regex: SafeRegex               // 時間の上限を持つ照合器（§5.6）
    let health: RegexPatternHealth     // 打ち切られたパターンの記録
}
```

## 5.2 巻数の照合

```swift
public enum VolumeMatcher {
    /// 指定位置から始まる候補を**長い順（同長なら登録順が先のもの）**で返す。
    /// `@volume` の型付き照合 [TY-01][SE-24] に使う。**区切り専用は候補にしない。**
    public static func matches(in subject: FoldedSubject, at index: Int,
                               patterns: [CompiledVolumePattern],
                               includeBareDigits: Bool = true) -> [VolumeMatch]

    /// 末尾にちょうど届く一致 [SE-02]。**区切り専用もここでは候補になる。**
    public static func matchAtEnd(_ subject: FoldedSubject,
                                  patterns: [CompiledVolumePattern]) -> VolumeMatch?
}

public struct VolumeMatch: Sendable, Equatable {
    public let patternID: UUID?        // 生の数字表記のときは nil
    public let range: Range<Int>       // 入力（文字添字）における範囲
    public let value: VolumeValue
}
```

照合はパターンごとに 2 本のコンパイル済み正規表現を使う。位置アンカー用（`.anchored`）と、
末尾アンカー用（`(?:…)\z` で包んだもの）。**`(?:` は非キャプチャなのでグループ番号は
ずれない。**

| # | 要件 |
|---|---|
| VM2-01 | **末尾に届く一致のうち最長のものを採る。同じ長さなら登録順が先のもの** [SE-21]。<br>**[実装との差異、2026-08]** 当初は「登録順に評価し最初にマッチしたもの」としていたが、それだけでは登録順に対して脆い。既定セットが `??巻` を `第??巻` より先に列挙していた頃、その順だと `作品 第01巻` が `01巻` と読まれて**シリーズ名が `作品 第` になる**（実測で再現）。実データの一般コミックは 94% が `第??巻` なので実害が大きい。登録順は同点の決着にのみ使う [設計判断]。回帰テストは `VolumeMatcherTests.robustAgainstRegistrationOrder` |
| VM2-02 | 区切り専用（`kind == .separator`）は**範囲は返すが巻数は `.none`**。シリーズ名を切るのが役目 |
| VM2-03 | 巻数種別でキャプチャが**数値として読めない**パターンは候補にしない。`第(.)巻` を巻数 0 と誤って扱うより、一致しなかったことにするほうが害が小さい |
| VM2-04 | 全角数字は畳んだ射影の側で既に半角になっている。`raw` には原文を保持する [SE-03] |
| VM2-05 | `@volume` の型条件は「生の数字表記（`01` `3` `3.5`）」＋「**巻数種別**の正規表現」の和集合 [SE-24]。生の数字表記だけは正規表現を通さない——型条件の一部として常に必要で、ユーザーが書き換えられるものでもないため |
| VM2-06 | 時間の上限で打ち切られたパターンは、その設定スナップショットが生きている間**二度と試さない**（§5.6）。呼び出し側は理由付きで 1 度だけユーザーへ知らせること [ER-02] |

## 5.3 シリーズ抽出 [10.1 節]

```swift
public enum SeriesExtractor {
    public struct Output: Sendable {
        public let seriesName: String?     // nil = @series 無効 [SE-07]
        public let volume: VolumeValue
        public let volumeRange: Range<String.Index>?
    }

    /// @series を直接書いていないフォーマットにマッチした場合に呼ぶ。 [SE-02]
    public static func extract(fromTitle title: String,
                               patterns: [CompiledVolumePattern]) -> Output
}
```

```pseudo
extract(title, patterns):
    t = title
    m = matchAtEnd(t, patterns)          # 末尾からの巻数照合 [SE-02]
    if m == nil:
        return Output(seriesName: nil, volume: .none, volumeRange: nil)   # [SE-07]
    series = t[..<m.range.lowerBound]
    series = trimWhitespace(series)      # 末尾の空白を除去 [SE-02]
    if series.isEmpty:
        return Output(seriesName: nil, volume: m.value, volumeRange: m.range)
    return Output(seriesName: series, volume: m.value, volumeRange: m.range)
```

### 直接指定との関係 [RW-06〜RW-10]

| フォーマットの記述 | シリーズ名 | 巻数 | `@title` からの除去 |
|---|---|---|---|
| `@series` あり | `@series` の値をそのまま [SE-02a] | `@volume` があればその値、なければ `.none` | **行わない** [RW-08] |
| `@volume` のみあり | `@title` から `@volume` 相当の表記を除去して導出 [RW-10] | `@volume` の値 | 行わない（`@volume` 相当のみ除去） |
| どちらもなし | `@title` 末尾から巻数を除去して導出 [SE-02] | 抽出した巻数 | 行う |
| `@series` と `@title` の両方 | `@series` の値 | 上に同じ | 行わない。`@title` は独立フィールド [RW-09] |

| # | 要件 |
|---|---|
| SE2-01 | `@series` が無効（nil）の場合、紐づけられたラベルグループへのラベル生成・付与を行わない [SE-08] |
| SE2-02 | 抽出した巻数は `ManagedFile.volumeNumber` / `volumeKind` / `volumeRaw` に保存し、ライブラリ表示モードのソートに使う [SE-09][VM-15] |
| SE2-03 | 巻数フォーマットの変更は既存ファイルへの再適用を促す [AT-04][TY-06] |
| SE2-04 | 編集画面ではサンプルタイトルに対してシリーズ名・巻数の抽出結果をプレビューする [SE-22] |
| SE2-05 | `@title` が存在しないフォーマット（`@series` + `@volume` のみ）では、ライブラリ表示モードの表示名を `seriesTitleCompositionFormat`（既定 `@series @volume`）で合成する [SE-33] |

## 5.4 巻数フォーマットセット [11.3 節]

`Sources/QooKit/Resources/Templates/volume-sets.json` に定義する [MT-02]。
`QooKit` のリソースとして持つことで、テストからも同じ定義を参照できる。

```jsonc
{
  "sets": {
    "VS-Full": [
      { "source": "第([0-9]+(?:\\.[0-9]+)?)巻" },
      { "source": "([0-9]+(?:\\.[0-9]+)?)巻" },
      { "source": "(?i:vol(?:ume)?)\\.?\\s*([0-9]+(?:\\.[0-9]+)?)" },
      { "source": "[\\s_-]+[vV]([0-9]+(?:\\.[0-9]+)?)" },
      { "source": "[vV]([0-9]+(?:\\.[0-9]+)?)" },
      { "source": "_([0-9]+(?:\\.[0-9]+)?)" },
      { "source": "(上巻|中巻|下巻|最終巻|前編|中編|後編|完結編|総集編)", "kind": "separator" },
      { "source": "総集編([0-9]+)", "kind": "separator" }
    ],
    "VS-Doujin": [ "…VS-Full から [vV] 系と _ 系を除いたもの…" ],
    "VS-None": []
  }
}
```

**19 本あった巻数パターンが 6 本になった。** `vol` / `Vol` / `VOL` / `volume` /
`Volume` の揺れを `(?i:vol(?:ume)?)` の 1 本で表せるため。

| 決めごと | 理由 |
|---|---|
| `([0-9]+(?:\.[0-9]+)?)` と書く | `3.5 巻` のような小数を落とさないため。旧記法の `??` が元から許していた性質で、**素朴に `([0-9]+)` と書くと静かに失われる**（実測で踏んだ）。小数が不要なら `([0-9]+)` でよい |
| `(?i:…)` で大文字小文字を無視 | 列挙で書くと `Vol` のような組み合わせを取りこぼす。**実際、当初案は `Vol.01` を拾えなかった** |
| `kind` を省略したら `volume` | 大半が巻数パターンなので、既定を短く書けるほうがよい |
| 区切り専用は VS-Full / VS-Doujin で共通 | 一般コミックにも `上巻` は現れるし、余分な語があっても害が無い［ユーザー判断］ |
| `\s*([0-9]+)`（空白＋数字だけ）は既定に含めない | タイトル末尾の数字を巻数と誤認する影響が大きい。必要なユーザーが自分で追加する [10.2 節の注記を反映] |

**列挙順は同じ長さに一致したときの決着にのみ使う** [SE-21]。照合は最長一致が
優先されるので、`第([0-9]+)巻` と `([0-9]+)巻` の順序に結果は依存しない [VM2-01]。

## 5.5 巻数の出力書式 [CR-20〜CR-25]

変換リネームの出力側で使う。

```swift
public struct VolumeOutputStyle: Sendable, Hashable, Codable, Identifiable {
    public let id: UUID
    public var name: String                    // 名前を付けて共有できる [CR-25]
    public var numericTemplate: String = "第{n}巻"   // {n} が数値プレースホルダ [CR-22]
    public var digits: Int = 2                       // 0 = ゼロ埋めしない [CR-22]
    public var numeralWidth: NumeralWidth = .halfwidth  // 半角／全角 [CR-22]
    public var noneOutput: String = ""                  // [CR-22]
    // `ordinalTemplate` は序列巻数の廃止（§5.1）で削除した。

    public enum NumeralWidth: String, Sendable, Codable { case halfwidth, fullwidth }
}

public enum VolumeFormatter {
    public static func render(_ v: VolumeValue, style: VolumeOutputStyle) -> String
}
```

```pseudo
render(v, style):
    switch v.kind:
      case .none:    return style.noneOutput
      case .numeric:
          n = v.number!
          s = (n == n.rounded() && n.magnitude < 1e15)
                ? String(Int(n))
                : String(n)                        # 3.5 は "3.5"
          # ゼロ埋めは整数部にのみ適用
          if style.digits > 0:
              intPart, fracPart = split(s, at: ".")
              intPart = intPart.leftPad("0", to: style.digits)
              s = fracPart == nil ? intPart : intPart + "." + fracPart
          if style.numeralWidth == .fullwidth: s = toFullwidthDigits(s)
          return style.numericTemplate.replacing("{n}", with: s)
```

### 変換例（要件 10.3 節の表と一致すること）

| 入力 | 種別 | 書式 | 出力 |
|---|---|---|---|
| `(01)` | numeric 1 | `第{n}巻` / 2 桁 | `第01巻` |
| `(3)` | numeric 3 | `第{n}巻` / 2 桁 | `第03巻` |
| `(vol.12)` | numeric 12 | `第{n}巻` / 2 桁 | `第12巻` |
| `(上巻)` | **none**（区切り専用に一致し巻数を持たない） | `""` | （出力なし） |
| `(前編)` | **none**（同上） | `""` | （出力なし） |
| なし | none | `""` | （出力なし。CR-30 で周囲ごと削除） |

| # | 要件 |
|---|---|
| VO-01 | 数値テンプレートに当たるのは**数値巻数だけ**。`第上巻巻` のような破綻は構造的に起こらない [CR-23]。以前は序列専用のテンプレートを分けることで防いでいたが、序列巻数そのものを廃止したので、書式に当てはまる種別が 1 つになった |
| VO-02 | 出力フォーマットに `第@volume巻` のように固定文字列を直接書くことは構文上許容するが、保存時に警告する [CR-24] |
| VO-03 | `VolumeOutputStyle` は独立エンティティとして保存し、複数ルール・複数テンポラリフォルダから参照できる [CR-25] |

## 5.6 正規表現の暴走をどう防ぐか

ユーザーが書いた正規表現は**指数時間**になりうる。ICU で `(a+)+$` は 2 文字
増えるごとに約 4 倍（a×26 で 2.75 秒、a×40 なら数時間規模）[実測]。1 ライブラリ
5 万ファイルの走査でこれを踏むとアプリは実質ハングする。

**三層で防ぐ。拒否ではなく警告にとどめる**——① が時間の上限を保証している以上、
表現力を削る理由が無い。

| 層 | 実装 | 内容 | **この層はどんな実条件で落ちるか** |
|---|---|---|---|
| ① 実行時ウォッチドッグ | `SafeRegex` | `enumerateMatches(options: [.reportProgress, …])` は**長時間の照合中にも定期的にブロックを呼ぶ**（50ms の間に約 500 回＝およそ 0.1ms 間隔）[実測]。`AppLimits.Format.regexMatchBudget`（20ms）を超えたら `stop.pointee = true` で打ち切る | 落ちない（時間の上限は実測で保証）。ただし**正当な低速マッチを黙って切る**ので通知が要る [ER-02] |
| ② 保存時の構造検査 | `RegexSafety.staticFindings` | 「量指定子の付いたグループが中にも量指定子や選択肢を含む」形（指数時間の必要条件）・後方参照・先読み・全角の文字を**警告**する | 経験則。安全なものを警告することも、危険なものを見逃すこともある |
| ③ 保存時の実測 | `RegexSafety.measuredFindings` | パターン自身のリテラルから作った敵対的文字列と実サンプルへ当てて計測する。**① と同じウォッチドッグの下で走るので検査自体は固まらない** | 破裂させる文字列が標本に無いパターンを見逃す |

**③ を `validate()` に混ぜてはならない。** `validate()` は設定画面の描画のたびに
（セクションの数だけ）呼ばれるので、実測を混ぜると**危険な正規表現を直している
最中にこそ画面が重くなる**という、いちばん困る形になる。実測は
`LibrarySettingsDraft.measuredIssues(samples:)` として分けてある。

### 打ち切られたパターンの扱い [VM2-06]

打ち切られたパターンを使い続けると、**1 ファイルごとに時間の上限ぶんだけ待つ**
ことになる（5 万ファイルなら 20ms × 5 万 = 17 分）。`RegexPatternHealth` が
記録し、同じ設定スナップショットの中では二度と試さない。

### 実測値（この設計の根拠）

| 測ったこと | 結果 |
|---|---|
| ICU の破滅的バックトラッキング | `(a+)+$` が 2 文字ごとに約 4 倍。a×26 で 2.75 秒 |
| Swift 標準の `Regex` の同じパターン | a×20 で **60 秒**（ICU の約 1,500 倍）。打ち切る手段も無い |
| `.reportProgress` での打ち切り | a×34（無制限なら約 700 秒）が**正確に 0.050 秒**で停止 |
| ウォッチドッグのオーバーヘッド | 0.0016 → 0.0028 ms/件。一致件数は完全に同一 |
| 移行後の全体パース（T-05） | **0.049 ms/件**（旧実装 0.078 ms/件。目標 1 ms/件）——`matchAtEnd` が開始位置を総当たりしなくなったぶん速くなった |

## 5.7 ComicInfo.xml の巻数（第 2 部の調査結果。**実装はまだ無い**）

EPUB / PDF / ComicInfo.xml のメタデータ読み取りは別の作業単位だが、調べた結果を
失うと再調査になるのでここに残す。

**公式スキーマ（Anansi Project）の定義**:

- `Number` = "Number of the book in the series"（シリーズ内の通し番号）
- `Volume` = "Volume containing the book. **Volume is a notion that is specific to
  US Comics**, where the same series can have multiple volumes"（＝リブートや
  第 2 期のような「版」）

つまり**日本のマンガの「巻数」は本来 `Number` 側**で、`Volume` は別概念。その上で
実装は割れている:

| フィールド | Komga | Kavita | 公式定義 |
|---|---|---|---|
| `Number` | **本の番号（＝巻数）** | Issue / Chapter number（話数） | シリーズ内の通し番号 |
| `Volume` | **シリーズ名に付加**（`Series (Volume)` と表示） | **Volume（＝巻数）** | US コミック特有の「版」 |

**真逆に近い。** Komga は公式定義に忠実、Kavita は日本のマンガ運用に寄せている。
日本語のタグ付けツールは Kavita 流（`Volume` に巻数）が多い一方、公式準拠の
ツールは `Number` に入れる。

**決めたこと**［ユーザー判断］: 両方あって数字が食い違う場合は**ファイルごとに
ユーザーへ確認する**（「以降すべてに適用」つき）。同じ数字か片方だけならそれを
巻数とする。
