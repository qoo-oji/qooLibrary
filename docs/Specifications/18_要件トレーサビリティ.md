## 18.4 逆引き — 本仕様書で新たに定めた事項（`[設計判断]`）

要件定義書に記載がなく、本仕様書で決めた事項の一覧。実装時に再検討してよい。

| 章 | 事項 | 理由 |
|---|---|---|
| 00 §0.5 | Swift 6 言語モード + StrictConcurrency | データ競合をコンパイル時に検出 |
| 01 B-03 | UnRAR は Objective-C++ ラッパー経由 | ビルド安定性。T-13 の結果で見直す |
| 01 B-21 | フルディスクアクセスの判定は TCC 保護領域への読み取り試行 | 照会 API が存在しない |
| 02 §2.7 | 操作履歴の記録起点を `FileOperationService` と `CommandStack` に限定 | 記録漏れを構造的に防ぐ |
| 03 NM-01/NM-02 | 全角→半角は自前の変換表。半角カナと長音を変換しない | `CFStringTransform` が日本語タイトルを壊すため |
| 04 VD-02 | elastic 空白は自由文字列フィールドの境界とみなさない | 境界が決定できないため TY-05 と同じ扱い |
| 04 MT2-02 | 探索ノード数の上限 20,000 | 病的なフォーマットでの停止を防ぐ |
| 04 PTI-05 | 保護文字列のプレースホルダは PUA U+E000〜U+E0FF（256 個）| 実用上十分 |
| 05 VM2-03 | `総集編??` は `.ordinal` として扱う | 種別を 1 つに定めないと CR-22 が破綻する |
| 05 §5.4 | `<space>??` を VS-Full / VS-Doujin の既定に含めない | 10.2 節の注記（誤認の影響が大きい）に従う |
| 06 AR3-01 | `.nameAnywhere` は最初の一致 1 箇所のみ置換 | 全置換は非冪等になりやすい |
| 09 QL2-08 | Quick Look は App Extension を使わず `QLPreviewPanel` に「書き出したカバー画像ファイルの URL」を渡して実装 | 公証なしの配布形態と相性が良い。項目ごとの独自ビューを差し込む API は `QLPreviewPanel` に存在しない（SDK ヘッダで確認） |
| 09 QL2-02 | 独自プレビューの対象を要件 QL-03 の cbz/cbr/cb7 から、対応アーカイブ全般＋フォルダへ広げた | `.zip` と `.cbz` を同一視する本アプリで拡張子ごとに挙動が変わるのを避ける。QL-08 のブックフォルダも先取りで満たせる |
| 11 MW2-04 | **タブは macOS ネイティブのウインドウタブに委ねる**（当初の「アプリ内タブとして自前実装する」を撤回した）| Finder のタブはそもそもネイティブのウインドウタブであり、外観・仕様を独自実装で寄せる方向に勝ち目が無い。1 ウインドウ＝1 タブになるので `WindowState` の自前管理も不要になり、MW-03 が無償で満たされた |
| 12 §12.7 | 整合性チェックの修復は項目単位。自動修復しない | 誤修復でラベルを失うリスクを避ける |
| 13 §13.2 | 要件 8.1 節の 10 色表はアルゴリズム生成の「結果例」として扱う | MT-13 の明文に従う |
| 16 §16.6 | T-13 / T-12 をフェーズ 0 に前倒し | 設計判断が覆ったときの手戻りが最大のため |
