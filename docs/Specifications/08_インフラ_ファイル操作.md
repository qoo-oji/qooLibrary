## 8.1 FileOperationService [FO-01]

**ファイルシステムへの変更はすべてこのサービスを経由する。** 他のレイヤから `FileManager` の変更系 API を呼んではならない。CI の静的検査 B-10 で強制する [FO-02]。

```swift
public actor FileOperationService {
    public init(ledger: ExpectedChangeLedger,
                history: OperationHistoryStore,
                bookmarks: BookmarkResolving,
                logger: DiagnosticLogging)

    // MARK: - 基本操作 [7.1 節]
    public func createDirectory(at: URL, options: OpOptions) async throws -> OpReceipt   // [FM-01]
    public func copy(_ items: [URL], to: URL, options: OpOptions) async throws -> [OpReceipt] // [FM-02]
    public func move(_ items: [URL], to: URL, options: OpOptions) async throws -> [OpReceipt] // [FM-03]
    public func rename(_ item: URL, to newName: String, options: OpOptions) async throws -> OpReceipt // [FM-05]
    public func trash(_ items: [URL], options: OpOptions) async throws -> [TrashReceipt] // [FM-04]
    public func deletePermanently(_ items: [URL], options: OpOptions) async throws -> [OpReceipt] // [FM-14]
    public func restoreFromTrash(_ receipts: [TrashReceipt]) async throws                // [UD-08]

    // MARK: - 一括・2 パス
    /// 循環リネームに対応した 2 パス実行 [BR-10][CR-52]
    public func renameBatchTwoPass(_ plan: [(from: URL, toName: String)],
                                   options: OpOptions) async throws -> BatchSummary

    // MARK: - ステージングからの移送 [EX-04]
    public func promoteFromStaging(_ staging: URL, to destination: URL,
                                   options: OpOptions) async throws -> [OpReceipt]
}

public struct OpOptions: Sendable {
    public var conflictPolicy: ConflictPolicy = .ask       // [FM-11]
    public var suppressAutoRename: Bool = false            // [CR-63][PW-15]
    public var suppressFSEvents: Bool = false              // 一括中の監視停止 [FO-14]
    public var commandContext: CommandContext?             // Undo/履歴の起点 [FO-03]
    public var progress: ProgressReporter?
}

public enum ConflictPolicy: Sendable {
    case ask                     // ダイアログ [FM-11]
    case replace                 // [FM-13]
    case keepBoth                // 連番付与
    case skip
}

public struct OpReceipt: Sendable {
    public let before: FileIdentity?
    public let after: FileIdentity?
    public let fromURL: URL
    public let toURL: URL
    public let kind: OperationKind
}
```

|---|---|

| FS2-02 | xattr 書き込み API を持たない [CL-03] |

| FS2-04 | すべての操作は実行前に対象ボリュームのオンライン状態を確認する。オフラインなら `.volumeOffline` で失敗する [VD-11] |
| FS2-05 | シンボリックリンク・エイリアスは追跡しない。リンク自体を 1 項目として扱う [SL-01] |

## 8.2 期待変更台帳 [FO-11〜FO-13]

自己変更を FSEvents から確実に除外するための主たる手段。

```swift
public actor ExpectedChangeLedger {
    public struct Entry: Sendable, Hashable {
        public let volumeUUID: String
        public let inode: UInt64?          // 作成時は nil（まだ存在しない）
```

### 4 層の自己変更識別 [5.4 節]

| 層 | 実装 |
|---|---|
| 1 | `FSEventStreamCreate` に `kFSEventStreamCreateFlagIgnoreSelf` を指定。**一次フィルタとしてのみ位置づける** [FO-10] |
| 2 | 期待変更台帳。主たる識別手段 [FO-11〜FO-13] |
| 3 | 一括操作中の監視停止。完了後に差分照合を 1 回 [FO-14][FO-15] |

| # | 要件 |
|---|---|
| LG3-01 | 台帳の照合キーは `(volumeUUID, inode, path)` の**いずれか一致**で緩めに判定する。移動先ではまだ inode が確定していないためパスで照合する |
| LG3-02 | 期限切れエントリは以後「外部変更」として扱う [FO-13] |
| LG3-03 | 一括操作（一括リネーム・変換リネーム・一括移動・一括アーカイブ）中は対象フォルダの監視を停止する。この集合は 5.6 節の排他処理と同一 [FO-14] |

## 8.3 衝突処理 [FM-11〜FM-13]

```swift
public struct ConflictDecision: Sendable {
```

```pseudo
resolveConflict(src, dest, options, session):
    if !exists(dest): return .proceed
    switch options.conflictPolicy:
      case .ask:
          d = await session.ask(.nameCollision(src, dest))    # 強度 2 シート [ER-11]
          if d.applyToAll: options.conflictPolicy = d.policy
          return d
      case .replace:
          # 置換されるファイルの DB レコードを削除し、
          # 置き換えたファイルへラベルを引き継ぐか確認する [FM-13]
      case .keepBoth: dest = nextAvailableName(dest)   # "name 2.cbz"
      case .skip:     return .skip
```

```pseudo
isBookFolder(url, target, image, entries):
```
